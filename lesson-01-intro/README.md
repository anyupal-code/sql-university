## Цель урока

## Теория

### 1. Назначение баз данных
Файловое хранение (CSV, Excel) имеет ограничения: отсутствие конкурентного доступа (при одновременном изменении данные теряются), низкая целостность и медленный поиск.  
Реляционные базы данных (например, PostgreSQL) обеспечивают надежное хранение и быстрый доступ.

### 2. Архитектура «клиент-сервер»
PostgreSQL — сервер. Он работает в фоне (как служба) и слушает порт (по умолчанию 5432).  
Клиент подключается к серверу по сети (или локально) и отправляет SQL-запросы. Сервер обрабатывает их и возвращает результат. 

В отличие от SQLite (где база данных — это файл), PostgreSQL — отдельный процесс, требующий администрирования. 

### 3. Роли и пользователи
В PostgreSQL есть суперпользователь `postgres`. Работа под ним небезопасна.  
Корректный подход: создание отдельного пользователя (например, `myuser`) и базы данных (например, `mydb`).  

### 4. Графический клиент (DBeaver)
DBeaver — бесплатный кроссплатформенный клиент с подсветкой синтаксиса, просмотром таблиц и поддержкой ER-диаграмм.
