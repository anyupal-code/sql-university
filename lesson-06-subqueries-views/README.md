# Урок 6. Подзапросы и представления (Views)

## Цель урока
Освоить подзапросы (вложенные запросы) для решения сложных задач и научиться создавать представления (Views) для упрощения работы с данными.

## Что потребуется для этого урока
* PostgreSQL (запущенный локально).
* DBeaver.
* Таблицы `customers` и `orders` (созданные в Уроке 4).

---

## Теория

### 1. Подзапросы (Subqueries)
Подзапрос — это SQL-запрос внутри другого запроса. Он используется для получения промежуточного результата, который затем используется во внешнем запросе.
**Где можно использовать:**
* В `SELECT` (как колонка).
* В `FROM` (как временная таблица).
* В `WHERE` (для фильтрации).

*Пример (в WHERE):* Найти клиентов, у которых есть заказы на сумму больше 50000.
~~~sql
SELECT name FROM customers 
WHERE id IN (
    SELECT customer_id FROM orders WHERE amount > 50000
);
~~~

### 2. Представления (Views)
`VIEW` (Представление) — это виртуальная таблица, основанная на результате запроса. Она не хранит данные, а просто сохраняет сам запрос.
**Зачем нужны:**
* Скрывают сложность (вместо длинного запроса используется имя).
* Ограничивают доступ (можно дать пользователю доступ к View, но не к таблице).

*Пример:* Создать представление для клиентов с их суммарными покупками.
~~~sql
CREATE VIEW customer_totals AS
SELECT c.name, SUM(o.amount) as total
FROM customers c
JOIN orders o ON c.id = o.customer_id
GROUP BY c.name;
~~~
Теперь можно обращаться к этому View как к обычной таблице:
~~~sql
SELECT * FROM customer_totals WHERE total > 50000;
~~~

### 3. Применение в разработке
* **Подзапросы:** Аналитика, сложная фильтрация, поиск отклонений.
* **Views:** Безопасность (скрываем пароли), упрощение отчетов (менеджеры работают с готовыми View, а не с таблицами).
