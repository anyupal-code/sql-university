# Практическое задание к Уроку 8

## Цель работы
Научиться управлять транзакциями для обеспечения целостности данных и на практике увидеть, как работает `ROLLBACK`.

## Что нужно сделать

### Шаг 1. Создание таблицы счетов
Выполните скрипт для создания таблицы `accounts`:

~~~sql
CREATE TABLE accounts (
    id SERIAL PRIMARY KEY,
    owner VARCHAR(100),
    balance DECIMAL(10, 2)
);

INSERT INTO accounts (owner, balance) VALUES 
('Иван', 5000.00),
('Мария', 3000.00);
~~~

### Шаг 2. Успешная транзакция (перевод)
1. Начните транзакцию: `BEGIN;`
2. Спишите 1000 рублей у Ивана.
3. Зачислите 1000 рублей Марии.
4. Подтвердите транзакцию: `COMMIT;`
5. Проверьте баланс обоих счетов: `SELECT * FROM accounts;`

*Ожидаемый результат:* У Ивана 4000, у Марии 4000.

### Шаг 3. Откат транзакции (имитация сбоя)
1. Начните транзакцию: `BEGIN;`
2. Спишите 500 рублей у Ивана.
3. (Представьте, что в этот момент произошел сбой, и мы не успели зачислить деньги Марии).
4. Откатите транзакцию: `ROLLBACK;`
5. Проверьте баланс: `SELECT * FROM accounts;`

*Ожидаемый результат:* Балансы остались прежними (4000 и 4000). Деньги Ивана не списались, так как транзакция была отменена.

### Шаг 4. Проверка изоляции (опционально)
Попробуйте открыть два окна SQL в DBeaver.
1. В первом окне начните транзакцию (`BEGIN`) и измените баланс.
2. Во втором окне выполните `SELECT * FROM accounts;`.
3. Убедитесь, что второе окно не видит изменений, пока вы не выполните `COMMIT` в первом окне.

---

## Ожидаемый результат
Вы понимаете, как транзакции защищают данные от частичных изменений. Вы умеете использовать `COMMIT` для сохранения и `ROLLBACK` для отмены.
