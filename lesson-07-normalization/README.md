## Теория

### 1. Проблема избыточности и аномалии
Представьте таблицу, где каждая строка содержит заказ клиента вместе с его адресом и городом. Если клиент сделает 100 заказов, его адрес будет продублирован 100 раз.
**Аномалии, к которым это приводит:**
* **Аномалия вставки:** нельзя добавить нового клиента, пока он не сделал заказ.
* **Аномалия обновления:** если клиент сменил адрес, нужно обновить его во всех 100 строках. Ошибка в одной строке — и данные противоречивы.
* **Аномалия удаления:** если удалить последний заказ клиента, мы потеряем информацию о самом клиенте.

### 2. Нормализация
Нормализация — это процесс разбиения одной большой таблицы на несколько меньших, связанных между собой, чтобы устранить избыточность.

**Основные нормальные формы (Normal Forms):**
* **1НФ (Первая нормальная форма):** Атомарность. Каждая ячейка содержит только одно значение (никаких списков через запятую в одной ячейке).
* **2НФ (Вторая нормальная форма):** Каждый неключевой столбец зависит от всего первичного ключа (а не от его части).
* **3НФ (Третья нормальная форма):** Нет транзитивных зависимостей. Не должно быть колонок, которые зависят от других неключевых колонок.

**Главное правило:** Каждая таблица должна отвечать за одну сущность (клиенты, заказы, товары).

### 3. Практический пример
Вместо одной таблицы `orders` (id, customer_name, customer_city, product, price) мы создаем:
* `customers` (id, name, city) — информация о клиентах.
* `products` (id, name, price) — информация о товарах.
* `orders` (id, customer_id, product_id) — связующая таблица.

Это и есть нормализация — разбиение на сущности и связывание их через ID.

### 4. Применение в разработке
Любая профессиональная база данных (CRM, интернет-магазин, банк) проектируется с учетом нормализации. Это снижает количество ошибок, экономит место и делает систему надежной.
