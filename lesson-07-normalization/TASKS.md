# Практическое задание к Уроку 7

## Цель работы
Научиться выявлять избыточность данных и нормализовать таблицу, разбивая её на связанные сущности.

## Что нужно сделать

### Шаг 1. Анализ плохой таблицы
Представьте, что у вас есть одна таблица `orders_bad`:
~~~sql
CREATE TABLE orders_bad (
    order_id SERIAL PRIMARY KEY,
    customer_name VARCHAR(100),
    customer_city VARCHAR(100),
    product_name VARCHAR(100),
    product_category VARCHAR(100),
    quantity INT
);

INSERT INTO orders_bad (customer_name, customer_city, product_name, product_category, quantity) VALUES 
('Иван', 'Москва', 'Ноутбук', 'Электроника', 1),
('Иван', 'Москва', 'Мышь', 'Электроника', 2),
('Мария', 'Санкт-Петербург', 'Книга', 'Книги', 1),
('Мария', 'Санкт-Петербург', 'Ноутбук', 'Электроника', 1);
~~~

**Ответьте на вопросы (устно или в комментариях):**
1. В чем проблема этой таблицы?
2. Какие аномалии могут возникнуть при обновлении адреса клиента?
3. Какие сущности здесь можно выделить?

### Шаг 2. Нормализация
Разбейте таблицу `orders_bad` на три связанные таблицы:
1. **`customers`** (id, name, city)
2. **`products`** (id, name, category)
3. **`orders`** (id, customer_id, product_id, quantity)

*Подсказка:* используйте `FOREIGN KEY` для связи `orders` с `customers` и `products`.

### Шаг 3. Заполнение нормализованных таблиц
1. Заполните таблицу `customers` уникальными клиентами (Иван и Мария).
2. Заполните таблицу `products` уникальными товарами (Ноутбук, Мышь, Книга).
3. Заполните таблицу `orders`, ссылаясь на ID клиентов и товаров.

### Шаг 4. Проверка
Выполните запрос:
~~~sql
SELECT c.name, p.name, o.quantity
FROM orders o
JOIN customers c ON o.customer_id = c.id
JOIN products p ON o.product_id = p.id;
~~~
Убедитесь, что результат совпадает с исходными данными, но теперь данные хранятся без избыточности.
