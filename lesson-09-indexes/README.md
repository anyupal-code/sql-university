# Урок 9. Индексы и оптимизация

## Цель урока
Изучить, как индексы ускоряют поиск данных, понять, когда их использовать, и научиться анализировать план выполнения запроса (EXPLAIN ANALYZE).

## Что потребуется для этого урока
* PostgreSQL (запущенный локально).
* DBeaver.
* База данных `mydb`.

---

## Теория

### 1. Проблема полного перебора
Без индексов база данных при поиске нужной строки перебирает всю таблицу (Full Table Scan). Если в таблице 1 миллион строк, это может занять несколько секунд.  
**Индекс** (Index) — это структура данных (обычно B-Tree), которая ускоряет поиск, работая как алфавитный указатель в книге.  
Вместо перебора всех страниц вы сразу открываете нужную.

### 2. Создание индекса
Индекс создается для колонки, по которой чаще всего происходит поиск или фильтрация.
*Синтаксис:* `CREATE INDEX index_name ON table_name (column_name);`

*Пример:* Создать индекс на колонку `email` в таблице `customers`.
~~~sql
CREATE INDEX idx_customers_email ON customers (email);
~~~

### 3. Когда использовать индексы
**Использовать:**
* Колонки в `WHERE` (частые фильтры).
* Колонки в `JOIN` (связи между таблицами).
* Колонки в `ORDER BY` (сортировка).

**Не использовать:**
* Маленькие таблицы (до 1000 строк) — индекс не даст выигрыша.
* Колонки с малым количеством уникальных значений (например, `пол` — только М/Ж).

### 4. Плата за индексы
Индексы ускоряют чтение (`SELECT`), но замедляют запись (`INSERT`, `UPDATE`, `DELETE`). Каждый раз при изменении данных база должна обновить и индекс.  
Поэтому индексы нужно создавать только там, где они реально нужны.

### 5. Анализ запросов (EXPLAIN ANALYZE)
Оператор `EXPLAIN ANALYZE` показывает, как база данных будет выполнять запрос.  
* `Seq Scan` — полный перебор (медленно, индекса нет). 
* `Index Scan` — поиск по индексу (быстро). 

*Пример:*
~~~sql
EXPLAIN ANALYZE SELECT * FROM customers WHERE email = 'ivan@example.com';
~~~
Если в плане написано `Index Scan`, значит, индекс работает.
