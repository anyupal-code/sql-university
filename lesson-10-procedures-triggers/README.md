## Теория

### 1. Хранимые процедуры (Stored Procedures) и функции
**Хранимая процедура** (или функция) — это код на языке SQL (или PL/pgSQL), который сохраняется в базе данных и может быть вызван по имени.
**Зачем нужны:**
* **Повторное использование:** логика написана один раз и вызывается из разных мест.
* **Производительность:** код выполняется на сервере, данные не пересылаются по сети.
* **Безопасность:** можно дать доступ к процедуре, но не к таблицам.

*Синтаксис создания функции (PL/pgSQL):*
~~~sql
CREATE OR REPLACE FUNCTION get_total_orders(user_id INT)
RETURNS DECIMAL AS $$
BEGIN
    RETURN (SELECT SUM(amount) FROM orders WHERE customer_id = user_id);
END;
$$ LANGUAGE plpgsql;
~~~
*Вызов функции:* `SELECT get_total_orders(1);`

### 2. Триггеры (Triggers)
**Триггер** — это функция, которая автоматически выполняется **до** или **после** изменения данных (`INSERT`, `UPDATE`, `DELETE`) в таблице.
**Зачем нужны:**
* **Автоматическое обновление:** например, обновление колонки `updated_at` при изменении записи.
* **Аудит:** запись в лог, кто и когда изменил данные.
* **Проверка бизнес-правил:** запрет на удаление, если есть связанные записи.

*Синтаксис создания триггера:*
~~~sql
CREATE OR REPLACE FUNCTION update_timestamp()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER set_timestamp
BEFORE UPDATE ON orders
FOR EACH ROW
EXECUTE FUNCTION update_timestamp();
~~~

### 3. Инженерный вывод: когда использовать?
* **Процедуры:** для сложных вычислений и отчетов, которые часто вызываются.
* **Триггеры:** для поддержания целостности данных и автоматического аудита. 
* **Осторожно:** не стоит переносить всю бизнес-логику в БД, так как её сложнее тестировать и версионировать. Обычно триггеры используют для простых проверок и логов.
