# Краткий обзор курса SQL и баз данных

Этот файл содержит сводную информацию по всем темам курса для повторения перед собеседованиями или экзаменами.

---

## 1. Основы реляционных баз данных
* **Реляционная модель:** Данные хранятся в таблицах (строках и колонках).
* **Первичный ключ (PRIMARY KEY):** Уникальный идентификатор строки.
* **Внешний ключ (FOREIGN KEY):** Ссылка на первичный ключ другой таблицы (обеспечивает целостность).
* **Архитектура «клиент-сервер»:** PostgreSQL работает как сервер, клиент (DBeaver) подключается к нему по сети.

## 2. Базовый SQL (Выборка)
* `SELECT` (Выбрать) — получение данных.
* `WHERE` (Где) — фильтрация строк.
* `ORDER BY` (Упорядочить) — сортировка (`ASC` — по возрастанию, `DESC` — по убыванию).
* `LIMIT` (Лимит) — ограничение количества строк.
* `LIKE` (Похоже) — поиск по шаблону (`%` — любое количество символов, `_` — один символ).

## 3. Изменение данных (DML)
* `INSERT` (Вставить) — добавление новых строк.
* `UPDATE` (Обновить) — изменение существующих строк. **Всегда используйте `WHERE`!**
* `DELETE` (Удалить) — удаление строк. **Всегда используйте `WHERE`!**

## 4. Связи и объединение (JOIN)
* `INNER JOIN` — возвращает только совпадающие строки из обеих таблиц.
* `LEFT JOIN` — возвращает все строки из левой таблицы и совпадающие из правой (если нет — `NULL`).
* `RIGHT JOIN` — аналогично левому, но наоборот.
* `FULL OUTER JOIN` — возвращает все строки из обеих таблиц.

## 5. Агрегация и группировка
* **Агрегатные функции:** `COUNT` (количество), `SUM` (сумма), `AVG` (среднее), `MIN`/`MAX` (минимум/максимум).
* `GROUP BY` (Сгруппировать) — группировка строк для применения агрегатов.
* `HAVING` (Имея) — фильтрация групп (после `GROUP BY`), аналог `WHERE` для агрегатов.

## 6. Подзапросы и представления
* **Подзапрос:** Запрос внутри другого запроса (в `SELECT`, `FROM` или `WHERE`).
* **Представление (VIEW):** Виртуальная таблица на основе запроса (`CREATE VIEW`). Упрощает сложные запросы и ограничивает доступ.

## 7. Нормализация
* **1НФ:** Атомарность (каждая ячейка — одно значение).
* **2НФ:** Зависимость от всего первичного ключа.
* **3НФ:** Отсутствие транзитивных зависимостей.
* **Цель:** Устранение избыточности и аномалий (вставки, обновления, удаления).

## 8. Транзакции и ACID
* `BEGIN` — начало транзакции.
* `COMMIT` — подтверждение (сохранение).
* `ROLLBACK` — откат (отмена).
* **ACID:** Атомарность (все или ничего), Согласованность (корректность данных), Изолированность (независимость), Долговечность (сохранение после сбоя).

## 9. Индексы и оптимизация
* **Индекс:** Структура (B-Tree) для ускорения поиска.
* `CREATE INDEX` — создание индекса.
* **EXPLAIN ANALYZE:** Показывает план выполнения запроса (`Seq Scan` — медленно, `Index Scan` — быстро).
* **Минус индексов:** Замедляют вставку и обновление.

## 10. Хранимые процедуры и триггеры
* **Процедура/Функция:** Код на PL/pgSQL, сохраняемый в БД (`CREATE FUNCTION`).
* **Триггер:** Автоматическое действие при изменении данных (`BEFORE` / `AFTER`).
* **Применение:** Автообновление даты, аудит, проверка бизнес-правил.

## 11. Работа с БД из кода
* **Библиотеки:** `psycopg2` (Python), JDBC (Java), `libpqxx` (C++).
* **Параметризованные запросы:** Защита от SQL-инъекций (передача данных через параметры `%s` или `?`).
* **Курсор:** Объект для выполнения запросов и получения результатов.

---

## Инженерные правила выбора
1. **Для быстрого поиска:** Создавайте индексы на колонки в `WHERE` и `JOIN`.
2. **Для надежности:** Используйте транзакции (`BEGIN` / `COMMIT` / `ROLLBACK`).
3. **Для устранения дублирования:** Нормализуйте таблицы (разбивайте на сущности).
4. **Для безопасности:** Используйте параметризованные запросы при работе из кода.
5. **Для аналитики:** Применяйте `GROUP BY` и `HAVING` с агрегатными функциями.
