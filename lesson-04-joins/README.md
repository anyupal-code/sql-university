# Урок 4. Связи между таблицами (JOIN)

## Цель урока
Изучить типы связей между таблицами (1:1, 1:М, М:М) и научиться объединять данные из нескольких таблиц с помощью оператора JOIN.

## Теория

### 1. Зачем нужны связи и внешние ключи?
Хранить все данные в одной таблице неэффективно (дублирование). В реальных БД данные разбиваются на несколько таблиц, связанных между собой. 
Для обеспечения целостности используется **внешний ключ (FOREIGN KEY)** — колонка, которая ссылается на первичный ключ (PRIMARY KEY) другой таблицы.

**Основные типы связей:**
* **1:1 (Один к одному):** У пользователя один паспорт.
* **1:М (Один ко многим):** У одного клиента много заказов (самый частый тип).
* **М:М (Многие ко многим):** Один студент посещает много курсов, один курс посещают много студентов (реализуется через промежуточную таблицу).

### 2. Оператор JOIN
`JOIN` (Объединить) — позволяет извлекать данные из двух и более таблиц в одном запросе на основе их связей.

**Виды JOIN:**
* `INNER JOIN` (Внутреннее соединение) — возвращает только те строки, где есть совпадение в обеих таблицах.
* `LEFT JOIN` (Левое соединение) — возвращает все строки из левой таблицы и совпадающие из правой. Если совпадений нет, справа будут NULL.
* `RIGHT JOIN` (Правое соединение) — аналогично левому, но наоборот.

**Синтаксис (INNER JOIN):**
~~~sql
SELECT a.column1, b.column2
FROM table_a a
INNER JOIN table_b b ON a.id = b.a_id;
~~~

*Пример:* Выбрать имена клиентов и их заказы.
~~~sql
SELECT customers.name, orders.product
FROM customers
JOIN orders ON customers.id = orders.customer_id;
~~~

### 3. Практическое применение
JOIN используется повсеместно: 
* В интернет-магазинах (связь товаров и заказов).
* В социальных сетях (связь постов и комментариев).
* В CRM-системах (связь клиентов и сделок).
